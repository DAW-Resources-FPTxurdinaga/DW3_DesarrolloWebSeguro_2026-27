    Actividad 5. HTTPS y certificados digitales¶

    Objetivos¶

    Al finalizar esta actividad serás capaz de:

    • Comprender la diferencia entre HTTP y HTTPS.
    • Explicar por qué HTTPS protege las comunicaciones.
    • Identificar el papel de los certificados digitales.
    • Comprender la función de una Autoridad de Certificación (CA).
    • Inspeccionar un certificado digital utilizando el navegador.

    Material necesario¶

    Para realizar esta actividad necesitarás:

    • Capítulo "HTTPS y certificados digitales".
    • Navegador web.
    • Conexión a Internet.
    • Herramientas de desarrollo del navegador (opcional).

    Contexto¶

    Cuando un usuario accede a una aplicación web, la información viaja entre el navegador y el servidor.

    Si esa comunicación se realiza mediante HTTP, cualquier intermediario podría leer la información transmitida.

    HTTPS incorpora una capa de seguridad basada en certificados digitales y cifrado, garantizando que:

    • la información viaja cifrada;
    • el servidor puede demostrar su identidad;
    • el contenido no ha sido modificado durante la transmisión.

    Gracias a HTTPS es posible utilizar con seguridad aplicaciones como banca electrónica, comercio electrónico o plataformas educativas.

    Ejemplo guiado¶

    Observa la siguiente imagen.

    Ahora observa cómo interviene una Autoridad de Certificación.

    Cuando un navegador establece una conexión HTTPS ocurre, de forma simplificada, el siguiente proceso:

    1. El navegador solicita la página web.
    2. El servidor envía su certificado digital.
    3. El navegador comprueba que el certificado ha sido emitido por una Autoridad de Certificación de confianza.
    4. Si la comprobación es correcta, comienza la comunicación cifrada.

    Ejemplo aplicado a TxurdiGest¶

    Imagina que un profesor accede a TxurdiGest desde casa para introducir calificaciones.

    Si la aplicación utilizara únicamente HTTP:

    • el usuario podría enviar su contraseña sin cifrar;
    • un tercero podría interceptar la comunicación.

    Utilizando HTTPS:

    • las credenciales viajan cifradas;
    • el navegador verifica la identidad del servidor;
    • la comunicación resulta mucho más segura.

    Comprueba que lo has entendido¶

    Responde a las siguientes preguntas.

    1. ¿Qué diferencia existe entre HTTP y HTTPS?

    2. ¿Qué función tiene un certificado digital?

    3. ¿Qué papel desempeña una Autoridad de Certificación?

    4. ¿Por qué aparece un candado en la barra de direcciones del navegador?

    Actividad individual¶

    Prueba tú mismo

    Analiza el certificado digital de una página web segura.

    Puedes utilizar, por ejemplo:

    • https://www.google.com
    • https://github.com
    • https://www.ehu.eus
    • otra página que utilice HTTPS.

    Realiza los siguientes pasos.

    1. Abre la página.
    2. Haz clic sobre el icono situado junto a la dirección web (candado o información del sitio, según el navegador).
    3. Accede a la información del certificado.
    4. Observa los datos mostrados.

    Completa la siguiente tabla.

    Información Valor observado
    Dominio protegido
    Organización emisora
    Autoridad de Certificación
    Fecha de caducidad
    Algoritmo utilizado (si aparece)

    Analiza el certificado¶

    Responde.

    1. ¿Coincide el dominio del certificado con la página visitada?

    2. ¿Quién ha emitido el certificado?

    3. ¿Hasta cuándo es válido?

    4. ¿Qué ocurrirá cuando caduque?

    Tip

    Todos los certificados digitales tienen un periodo de validez limitado y deben renovarse periódicamente.

    Herramientas profesionales¶

    Navegador web¶

    Los navegadores permiten inspeccionar los certificados digitales instalados por un servidor.

    Esta información resulta muy útil para:

    • comprobar la identidad del servidor;
    • verificar la fecha de caducidad;
    • identificar la Autoridad de Certificación;
    • diagnosticar problemas relacionados con HTTPS.

    Note

    Aunque el navegador realiza automáticamente todas las comprobaciones, un desarrollador debe saber interpretar la información que proporciona el certificado.

    Aplicación en el reto¶

    La aplicación desarrollada durante el reto deberá desplegarse utilizando HTTPS.

    Aunque durante el desarrollo pueda utilizarse un entorno local, cualquier aplicación publicada en Internet deberá utilizar certificados digitales válidos.

    El equipo deberá comprender que:

    • el certificado identifica al servidor;
    • HTTPS protege las comunicaciones;
    • los navegadores verifican automáticamente la confianza del certificado.

    Errores habituales¶

    Warning

    Algunos errores frecuentes son:

    • Pensar que HTTPS protege una aplicación frente a cualquier ataque.
    • Ignorar los avisos del navegador sobre certificados no válidos.
    • Creer que el candado garantiza que una página es completamente segura.
    • Confundir cifrado con autenticación.

    Para recordar¶

    • HTTPS protege la comunicación entre navegador y servidor.
    • Los certificados digitales permiten identificar al servidor.
    • Una Autoridad de Certificación garantiza la confianza del certificado.
    • Los certificados tienen una fecha de caducidad.
    • Los navegadores verifican automáticamente la validez del certificado antes de establecer una conexión segura.
