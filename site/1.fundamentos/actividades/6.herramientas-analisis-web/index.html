    Actividad 6. Explorando una aplicación web con herramientas profesionales¶

    Objetivos¶

    Al finalizar esta actividad serás capaz de:

    • Identificar las principales herramientas utilizadas para analizar aplicaciones web.
    • Elegir la herramienta adecuada según la información que deseas obtener.
    • Observar el tráfico HTTP de una aplicación web.
    • Realizar una captura básica de tráfico de red.
    • Comprender las diferencias entre DevTools, curl, Burp Suite y Wireshark.

    Material necesario¶

    Para realizar esta actividad necesitarás:

    • Capítulo "Herramientas profesionales".
    • Navegador web.
    • DevTools del navegador.
    • curl.
    • Burp Suite Community.
    • Wireshark.
    • Conexión a Internet.

    Contexto¶

    Cuando una aplicación web no funciona correctamente, un desarrollador necesita averiguar qué está ocurriendo.

    ¿Se ha enviado la petición correcta?

    ¿Ha respondido el servidor?

    ¿Se ha creado la cookie de sesión?

    ¿La comunicación utiliza HTTPS?

    Responder a estas preguntas sería muy difícil sin herramientas de análisis.

    Cada herramienta proporciona una visión diferente de la aplicación y conocer cuándo utilizar cada una de ellas forma parte del trabajo habitual de cualquier desarrollador web.

    Ejemplo guiado¶

    Una misma aplicación puede analizarse desde distintos puntos de vista.

    Quiero saber... Herramienta recomendada
    Qué recursos descarga una página DevTools
    Qué cookies utiliza DevTools
    Qué responde una petición HTTP curl
    Todas las peticiones HTTP realizadas por una aplicación Burp Suite
    Todo el tráfico que circula por la red Wireshark

    Note

    Ninguna herramienta sustituye a otra. Cada una ofrece una perspectiva diferente del funcionamiento de una aplicación web.

    Ejemplo aplicado a TxurdiGest¶

    Durante el desarrollo de TxurdiGest el equipo quiere comprobar que el inicio de sesión funciona correctamente.

    Para ello puede utilizar:

    • DevTools para comprobar los recursos descargados y las cookies.
    • curl para realizar una petición HTTP concreta.
    • Burp Suite para observar todas las peticiones HTTP realizadas durante el inicio de sesión.
    • Wireshark para visualizar el tráfico generado por el equipo.

    Todas las herramientas analizan la misma aplicación, pero cada una proporciona información diferente.

    Comprueba que lo has entendido¶

    Responde a las siguientes preguntas.

    1. ¿Qué herramienta utilizarías para inspeccionar las cookies de una aplicación?

    2. ¿Cuál utilizarías para realizar una petición HTTP desde la terminal?

    3. ¿Qué herramienta permite observar todas las peticiones HTTP realizadas por una aplicación?

    4. ¿Qué herramienta captura todo el tráfico de una interfaz de red?

    Actividad individual¶

    Parte 1. DevTools¶

    Prueba tú mismo

    Abre una página web cualquiera.

    1. Abre DevTools.
    2. Accede a la pestaña Network.
    3. Recarga la página.
    4. Cuenta aproximadamente cuántas peticiones se realizan.
    5. Localiza al menos un archivo HTML, uno CSS, uno JavaScript y una imagen.

    Responde:

    • ¿Qué recurso tarda más tiempo en descargarse?
    • ¿Cuántas peticiones aparecen aproximadamente?

    Parte 2. Burp Suite Community¶

    Prueba tú mismo

    Utiliza el navegador integrado de Burp Suite.

    1. Inicia Burp Suite Community.
    2. Abre el navegador integrado (Open Browser).
    3. Accede a una página web.
    4. En Burp Suite selecciona Proxy → HTTP History.

    Observa la información registrada.

    Responde:

    • ¿Cuántas peticiones aparecen?
    • ¿Qué métodos HTTP observas?
    • ¿Qué códigos de estado aparecen con más frecuencia?

    Tip

    HTTP History registra automáticamente todas las peticiones realizadas desde el navegador integrado, sin necesidad de configurar manualmente el proxy del navegador habitual.

    Parte 3. Wireshark¶

    Prueba tú mismo

    Realiza una captura sencilla de tráfico.

    1. Inicia Wireshark.
    2. Selecciona tu interfaz de red.
    3. Comienza una captura.
    4. Visita durante unos segundos una página web.
    5. Detén la captura.

    Observa los paquetes capturados y responde:

    • ¿Qué protocolos aparecen?
    • ¿Observas tráfico DNS?
    • ¿Observas conexiones TLS?
    • ¿Cuántos paquetes se han capturado aproximadamente?

    No es necesario interpretar el contenido de los paquetes.

    El objetivo consiste únicamente en familiarizarse con la herramienta.

    Parte 4. ¿Qué herramienta elegirías?¶

    Relaciona cada situación con la herramienta más adecuada.

    Situación Herramienta
    Ver las cookies de una aplicación
    Realizar una petición HTTP manual
    Ver todas las peticiones HTTP de una aplicación
    Capturar todo el tráfico de la red

    Herramientas profesionales¶

    DevTools¶

    Permite analizar el funcionamiento de una página web desde el propio navegador.

    curl¶

    Permite realizar peticiones HTTP desde la línea de comandos.

    Es especialmente útil para probar APIs y comprobar respuestas del servidor.

    Burp Suite Community¶

    Actúa como un proxy entre el navegador y el servidor.

    Permite observar todas las peticiones y respuestas HTTP realizadas por una aplicación.

    En esta actividad únicamente se utiliza como herramienta de observación.

    Wireshark¶

    Captura el tráfico que circula por una interfaz de red.

    Permite visualizar protocolos de comunicación independientemente de la aplicación utilizada.

    Aplicación en el reto¶

    Durante el desarrollo del reto estas herramientas pueden ayudarte a:

    • comprobar que una petición llega correctamente al servidor;
    • verificar que las cookies de sesión se crean correctamente;
    • revisar las respuestas de una API;
    • confirmar que la aplicación utiliza HTTPS;
    • detectar problemas de comunicación entre cliente y servidor.

    Errores habituales¶

    Warning

    Algunos errores frecuentes son:

    • Pensar que Burp Suite solo sirve para realizar ataques.
    • Creer que Wireshark únicamente se utiliza en ciberseguridad.
    • Confundir el tráfico HTTP con todo el tráfico de red.
    • Elegir una herramienta cuando otra proporciona la información de forma mucho más sencilla.

    Más allá de la actividad¶

    Las siguientes propuestas son voluntarias. Están pensadas para quienes deseen profundizar en el uso de estas herramientas o descubrir nuevas posibilidades.

    Propuesta 1¶

    Explora la interfaz de Burp Suite.

    Localiza los apartados:

    • Proxy
    • HTTP History
    • Repeater
    • Target

    Sin utilizarlos, intenta deducir para qué sirve cada uno.

    Propuesta 2¶

    Realiza una captura con Wireshark mientras reproduces un vídeo o descargas un archivo.

    ¿Aumenta el número de paquetes?

    ¿Qué protocolos nuevos aparecen?

    Propuesta 3¶

    Busca información sobre Postman e Insomnia.

    ¿En qué situaciones utilizarías estas herramientas en lugar de curl?

    Investiga

    Muchas herramientas profesionales permiten analizar aplicaciones web.

    Busca información sobre alguna de ellas y explica:

    • cuál es su finalidad;
    • qué tipo de información proporciona;
    • en qué situaciones podría resultar útil para un desarrollador.

    Para recordar¶

    • Cada herramienta ofrece una perspectiva distinta del funcionamiento de una aplicación web.
    • DevTools analiza el comportamiento del navegador.
    • curl permite realizar peticiones HTTP desde la terminal.
    • Burp Suite observa el intercambio de mensajes HTTP entre cliente y servidor.
    • Wireshark captura el tráfico completo de una red.
    • Un buen desarrollador sabe elegir la herramienta más adecuada para cada situación.
