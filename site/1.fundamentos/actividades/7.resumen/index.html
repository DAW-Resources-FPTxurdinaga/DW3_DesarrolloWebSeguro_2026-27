    Actividad 7. Informe técnico de análisis de una aplicación web¶

    Objetivos¶

    Al finalizar esta actividad serás capaz de:

    • Integrar los conocimientos adquiridos a lo largo del Bloque 1.
    • Seleccionar la herramienta adecuada para obtener una determinada información.
    • Analizar una aplicación web desde el punto de vista de un desarrollador.
    • Elaborar un breve informe técnico con las observaciones realizadas.
    • Comprender la importancia de documentar el funcionamiento de una aplicación antes de modificarla.

    Material necesario¶

    Para realizar esta actividad necesitarás:

    • Navegador web.
    • DevTools.
    • curl.
    • Burp Suite Community.
    • Wireshark.
    • Conexión a Internet.
    • Una aplicación web accesible mediante HTTPS.

    Contexto¶

    Cuando un desarrollador comienza a trabajar en una aplicación existente, rara vez empieza escribiendo código.

    Lo primero que hace es comprender cómo funciona la aplicación.

    Para ello analiza las comunicaciones entre el navegador y el servidor, inspecciona las cookies, observa las peticiones HTTP y revisa el comportamiento general de la aplicación.

    En esta actividad realizarás ese mismo proceso utilizando las herramientas que has aprendido a lo largo del bloque.

    El objetivo no consiste en encontrar vulnerabilidades, sino en comprender el funcionamiento de la aplicación y documentar la información obtenida.

    Ejemplo guiado¶

    Antes de modificar una aplicación web, un desarrollador suele responder preguntas como estas:

    • ¿La aplicación utiliza HTTPS?
    • ¿Quién ha emitido el certificado digital?
    • ¿Qué recursos descarga el navegador?
    • ¿Qué cookies utiliza?
    • ¿Qué peticiones HTTP realiza?
    • ¿Qué tráfico genera el equipo?

    Cada una de estas preguntas puede responderse utilizando una herramienta diferente.

    Información que quiero obtener Herramienta
    Certificado digital Navegador
    Recursos descargados DevTools
    Cookies DevTools
    Peticiones HTTP Burp Suite
    Respuesta HTTP concreta curl
    Tráfico de red Wireshark

    Note

    Un desarrollador profesional combina distintas herramientas para comprender el funcionamiento de una aplicación antes de modificarla.

    Ejemplo aplicado a TxurdiGest¶

    Imagina que un nuevo desarrollador se incorpora al proyecto TxurdiGest.

    Antes de comenzar a implementar nuevas funcionalidades necesita comprender cómo funciona la aplicación.

    Durante unos minutos analiza el sistema utilizando distintas herramientas y documenta sus observaciones.

    Gracias a este proceso podrá trabajar con una visión mucho más completa del proyecto.

    Comprueba que lo has entendido¶

    Responde a las siguientes preguntas.

    1. ¿Por qué resulta útil analizar una aplicación antes de modificarla?

    2. ¿Qué herramienta utilizarías para comprobar el certificado digital?

    3. ¿Cuál utilizarías para observar todas las peticiones HTTP?

    4. ¿Qué información puede proporcionar Wireshark que no ofrece DevTools?

    Actividad individual¶

    Un equipo de desarrollo te ha pedido realizar un análisis preliminar de una aplicación web antes de comenzar una nueva fase del proyecto.

    Tu trabajo consiste en observar la aplicación utilizando las herramientas estudiadas durante este bloque y elaborar un pequeño informe técnico.

    No debes buscar vulnerabilidades ni modificar el funcionamiento de la aplicación.

    Tu objetivo es comprender cómo funciona.

    Herramientas profesionales¶

    Durante esta actividad has utilizado conjuntamente varias herramientas profesionales.

    Cada una aporta una visión diferente del funcionamiento de una aplicación.

    • DevTools permite analizar el comportamiento del navegador.
    • curl facilita realizar peticiones HTTP desde la línea de comandos.
    • Burp Suite registra las comunicaciones HTTP entre cliente y servidor.
    • Wireshark captura el tráfico completo de la red.

    Un desarrollador debe saber combinar todas ellas según la información que necesite obtener.

    Aplicación en el reto¶

    Antes de comenzar una nueva iteración del proyecto, el equipo puede utilizar este mismo procedimiento para revisar el estado actual de la aplicación.

    Este diagnóstico permite:

    • comprender el funcionamiento del sistema;
    • detectar posibles errores de configuración;
    • verificar que la aplicación utiliza HTTPS;
    • comprobar el comportamiento de las sesiones;
    • disponer de una visión global antes de implementar nuevas funcionalidades.

    Errores habituales¶

    Warning

    Algunos errores frecuentes son:

    • Analizar únicamente una herramienta y sacar conclusiones precipitadas.
    • Confundir el tráfico HTTP con el tráfico completo de la red.
    • Pensar que HTTPS garantiza por sí solo que una aplicación es completamente segura.
    • No documentar las observaciones realizadas.

    Más allá de la actividad¶

    Las siguientes propuestas son voluntarias. Están pensadas para quienes deseen profundizar en el análisis de aplicaciones web.

    Propuesta 1¶

    Compara dos aplicaciones web diferentes.

    ¿Qué diferencias observas en:

    • número de peticiones;
    • cookies utilizadas;
    • recursos descargados;
    • certificado digital?

    Propuesta 2¶

    Analiza una aplicación desarrollada durante el reto.

    ¿Qué aspectos revisarías antes de publicarla en Internet?

    Propuesta 3¶

    Busca información sobre otras herramientas utilizadas habitualmente para analizar aplicaciones web.

    ¿En qué situaciones podrían resultar útiles para un desarrollador?

    Investiga

    Busca información sobre el proceso de revisión técnica que realizan los equipos de desarrollo antes de publicar una aplicación.

    ¿Qué aspectos suelen comprobar además de los estudiados en este bloque?

    Para recordar¶

    • Analizar una aplicación es el primer paso antes de modificarla.
    • Cada herramienta proporciona una perspectiva diferente del funcionamiento del sistema.
    • Un desarrollador debe saber seleccionar la herramienta adecuada para cada situación.
    • Documentar las observaciones facilita el trabajo en equipo.
    • Comprender el funcionamiento de una aplicación permite desarrollar software más seguro.

    Cierre del Bloque 1¶

    🎉 ¡Enhorabuena! Has completado el primer bloque del módulo.

    A lo largo de estas actividades has aprendido a observar el funcionamiento de una aplicación web utilizando herramientas profesionales.

    Ahora eres capaz de:

    • comprender cómo se comunican el navegador y el servidor;
    • interpretar peticiones y respuestas HTTP;
    • analizar cookies y sesiones;
    • comprobar certificados digitales y conexiones HTTPS;
    • utilizar DevTools, curl, Burp Suite y Wireshark para obtener información sobre una aplicación web.

    En el siguiente bloque cambiarás de perspectiva.

    Hasta ahora has aprendido a observar una aplicación.

    A partir de este momento comenzarás a diseñarla y desarrollarla incorporando la seguridad desde las primeras fases del proyecto.

    Ese es el verdadero objetivo del desarrollo web seguro.
