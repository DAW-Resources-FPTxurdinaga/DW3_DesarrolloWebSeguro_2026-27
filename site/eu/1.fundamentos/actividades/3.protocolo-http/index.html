    3. jarduera. HTTP protokoloa¶

    Helburuak¶

    Jarduera hau amaitzean gai izango zara:

    • Nabigatzaile bat eta zerbitzari bat HTTP bidez nola komunikatzen diren ulertzeko.
    • HTTP eskaera bat eta HTTP erantzun bat bereizteko.
    • HTTP komunikazio baten elementu nagusiak identifikatzeko.
    • Oinarrizko metodoak, egoera-kodeak eta goiburuak interpretatzeko.
    • HTTP komunikazioak tresna profesionalak erabiliz aztertzeko.
    • Komando-lerrotik HTTP eskaerak egiteko curl erabiliz.

    Beharrezko materiala¶

    Jarduera hau egiteko honako hau beharko duzu:

    • "HTTP protokoloa" kapitulua.
    • Arakatzailea, garapen-tresnak aktibatuta dituena.
    • curl instalatuta duen terminala edo komando-konsola.
    • Interneteko konexioa, API publiko baten aurrean probak egiteko.
    • TxurdiGest azterketa-kasua.

    Testuingurua¶

    Erabiltzaile batek web aplikazio bat erabiltzen duenean, badirudi interfazea soilik erabiltzen ari dela.

    Hala ere, ekintza bakoitzak osagai desberdinen arteko komunikazioa sortzen du.

    Adibidez, ikasle batek TxurdiGest-en bere kalifikazioak kontsultatzen dituenean, honako hauen arteko komunikazioa gertatzen da:

    • Erabiltzailearen nabigatzailea.
    • Aplikazioaren zerbitzaria.
    • Informazioa biltegiratzen duen datu-basea.

    Nabigatzaileak informazioa eskatu behar du eta zerbitzariak dagokion datuekin erantzun behar du.

    Komunikazio hori HTTP protokoloaren bidez egiten da.

    HTTP ulertzea funtsezkoa da edozein web garatzailerentzat, erabiltzen den teknologia edozein dela ere.

    PHP, Laravel, Vue edo beste edozein framework erabiliz garatutako aplikazio batek ere HTTP eskaerak eta erantzunak erabiliko ditu.

    Adibide gidatua¶

    Begiratu ondorengo HTTP eskaera:

    GET /calificaciones HTTP/1.1
Host: txurdigest.local

    Eskaera honek informazio garrantzitsua dauka:

    Elementua Esanahia
    GET Informazioa eskatzeko erabilitako metodoa
    /calificaciones Eskatutako baliabidea
    HTTP/1.1 Erabilitako protokoloaren bertsioa
    Host Eskaera zuzentzen zaion zerbitzaria

    Zerbitzariak eskaera prozesatu eta erantzun bat itzultzen du:

    HTTP/1.1 200 OK
Content-Type: text/html

    Erantzunak ere informazio garrantzitsua dauka:

    Elementua Esanahia
    200 OK Eskaera behar bezala prozesatu da
    Content-Type Bidalitako eduki mota

    TxurdiGest-era aplikatutako adibidea¶

    Irakasle batek TxurdiGest-era sartzen da bere taldeko kalifikazioak kontsultatzeko.

    Prozesua honela izan liteke:

    1. Irakasleak aplikazioa nabigatzailetik irekitzen du.
    2. Nabigatzaileak HTTP eskaera bat sortzen du.
    3. Zerbitzariak eskaera jasotzen du.
    4. Aplikazioak beharrezko informazioa egiaztatzen du.
    5. Zerbitzariak erantzun bat itzultzen du.
    6. Nabigatzaileak emaitzak erakusten ditu.

    Aztertu ondorengo galderak:

    Hasierako komunikazioa¶

    • Nork hasten du beti komunikazioa?
    • Zer osagaik egiten du HTTP eskaera?

    Bidalitako informazioa¶

    Eskaerak honako hauek izan ditzake:

    • Eskatutako baliabidea.
    • Erabiltzaileak bidalitako datuak.
    • Nabigatzaileari buruzko informazioa.

    Jasotako informazioa¶

    Erantzunak honako hauek izan ditzake:

    • Egoera-kodea.
    • Eskatutako datuak.
    • Eragiketaren emaitzari buruzko informazioa.

    Erabiltzaileak pantaila bakarra ikusten badu ere, barnean HTTP komunikazio anitz gertatzen dira.

    Egiaztatu ulertu duzula¶

    Erantzun ondorengo galderei:

    1. Zer alde dago HTTP eskaera baten eta HTTP erantzun baten artean?

    2. Ondorengo eskaeran:

    GET /usuarios HTTP/1.1

    Adierazi:

    • Erabilitako metodoa.
    • Eskatutako baliabidea.

    • Protokoloaren bertsioa.

    • Zer esan nahi du zerbitzari batek ondorengo kodearekin erantzuteak?

    404 Not Found

    1. Zergatik egiaztatu behar du zerbitzariak beti nabigatzailetik jasotako informazioa?

    2. Zer alde dago DevTools erabiliz HTTP eskaera bat behatzearen eta curl erabiliz HTTP eskaera bat sortzearen artean?

    Banakako jarduera¶

    1. zatia. Eskaerak aztertzea DevTools-ekin¶

    Erabili nabigatzaileko garapen-tresnak web orri bat aztertzeko.

    Jarraitu urrats hauei:

    1. Ireki edozein web orri.
    2. Ireki nabigatzaileko garapen-tresnak.
    3. Sartu Network fitxara.
    4. Berrargitaratu orria.
    5. Behatu egindako eskaerak.

    Erregistratu ondorengo informazioa:

    Aztertutako elementua Emaitza
    Kargatutako baliabide nagusia
    Erabilitako HTTP metodoa
    Jasotako egoera-kodea
    Baliabide mota

    Ondoren erantzun:

    1. Zenbat eskaera egin dira orria kargatzean?
    2. Zer baliabide mota deskargatu dira?
    3. Ba al dago egoera-kode egokia itzultzen ez duen eskaerarik?

    2. zatia. HTTP eskaerak egitea curl-ekin¶

    curl garatzaileek sarritan erabiltzen duten tresna da HTTP eskaerak komando-lerrotik egiteko.

    APIak probatzeko, erantzunak aztertzeko eta komunikazio-arazoak diagnostikatzeko aukera ematen du.

    Oinarrizko GET eskaera¶

    Exekutatu:

    curl https://jsonplaceholder.typicode.com/users

    Behatu:

    • Jasotako datuak.
    • Erantzunaren formatua.
    • Zerbitzariak itzulitako informazioa.

    Erantzun:

    1. Zer HTTP metodo erabili da?
    2. Zer nolako datuak itzultzen ditu zerbitzariak?
    3. Erantzunak hainbat erabiltzaileren informazioa dauka?

    HTTP goiburuak kontsultatzea¶

    Exekutatu:

    curl -I https://jsonplaceholder.typicode.com/users

    Aztertu jasotako informazioa.

    Identifikatu:

    • HTTP egoera-kodea.
    • Eduki mota.
    • Zerbitzariari buruzko informazioa.

    POST eskaera bat egitea¶

    Exekutatu:

    curl -X POST \
-H "Content-Type: application/json" \
-d '{"nombre":"Ana","curso":"DAW"}' \
https://jsonplaceholder.typicode.com/posts

    Aztertu:

    • Erabilitako metodoa.
    • Bidalitako goiburua.
    • Eskaeraren gorputzean sarturiko datuak.

    Erantzun:

    1. Zer alde dago GET eta POST artean?
    2. Non bidaltzen dira datuak eskaera honetan?
    3. Zer informazio itzultzen du zerbitzariak?

    Tresna profesionalak¶

    Nabigatzaileko DevTools¶

    Garapen-tresnek web aplikazio batek sortutako HTTP komunikazioak behatzeko aukera ematen dute.

    Bereziki erabilgarriak dira honetarako:

    • eskaerak aztertzea;
    • erantzunak berrikustea;
    • egoera-kodeak egiaztatzea;
    • komunikazio-arazoak detektatzea.

    curl¶

    curl-ek nabigatzailerik erabili gabe HTTP eskaerak egiteko aukera ematen du.

    Sarritan honetarako erabiltzen den tresna da:

    • APIak probatzea.
    • Zereginak automatizatzea.
    • Zerbitzariaren erantzunak egiaztatzea.
    • Komunikazio-arazoak diagnostikatzea.

    Garatzaileek DevTools eta curl bezalako tresnak erabiltzen dituzte bezeroaren eta zerbitzariaren artean benetan zer gertatzen den ulertzeko.

    Erronkan aplikazioa¶

    Erronkako aplikazioaren garapenean, taldeak kontuan hartu behar du bezeroaren eta zerbitzariaren arteko komunikazio guztiak HTTP bidez egiten direla.

    Erabilitako teknologia edozein dela ere, aplikazioak eskaeren eta erantzunen truke bidez funtzionatuko du.

    Proiektua garatzean honako hauek aztertu beharko dira:

    • Bezeroak zer datu bidaltzen dituen.
    • Zer informazio itzultzen duen zerbitzariak.
    • Zer eragikatek behar duten babesa.
    • Erabiltzaile bakoitzak zer erantzun jasotzen duen.

    Taldeak funtzionalitateak inplementatzen dituenean gai izan behar du bere aplikazioak sortutako HTTP komunikazioak interpretatzeko.

    Ohiko akatsak¶

    Ohiko akats batzuk hauek dira:

    • Nabigatzaileak aplikazioaren segurtasuna kontrolatzen duela pentsatzea.
    • Bezeroarengandik zuzenean jasotako datuetan fidatzea.
    • Funtzionalitate bat ezkutatzeak inork ezin izango duela horretara sartu pentsatzea.
    • HTTP erantzun-kodeak ez berrikustea.
    • Bezeroaren eta zerbitzariaren artean trukatzen den informazioa ez ezagutzea.
    • APIak edo HTTP eskaerak erabiltzea, bidaltzen eta jasotzen diren datuak ulertu gabe.

    Gogoratzeko¶

    • HTTP bezeroaren eta zerbitzariaren arteko komunikaziorako erabiltzen den protokoloa da.
    • Web aplikazio batek eskaeren eta erantzunen bidez funtzionatzen du.
    • Eskaerek zerbitzariari bidalitako informazioa daukate.
    • Erantzunek eskatutako eragiketaren emaitza daukate.
    • DevTools-ek nabigatzaileak sortutako komunikazioak behatzeko aukera ematen du.
    • curl-ek HTTP eskaerak sortu eta aztertzeko aukera ematen du komando-lerrotik.
    • Zerbitzariak beti egiaztatu eta babestu behar du jasotako informazioa.
