    Actividad 1. Introducción al desarrollo web seguro¶

    Objetivos¶

    Al finalizar esta actividad serás capaz de:

    • Comprender que la seguridad debe integrarse desde el inicio de un proyecto web.
    • Identificar decisiones de seguridad asociadas a las diferentes fases del ciclo de vida del software.
    • Reflexionar sobre la importancia de anticipar riesgos durante el desarrollo.
    • Relacionar los conceptos estudiados con una situación real de desarrollo.

    Material necesario¶

    Para realizar esta actividad necesitarás:

    • Capítulo "Introducción al desarrollo web seguro".
    • Caso de estudio TxurdiGest.

    Contexto¶

    Un centro educativo quiere desarrollar una nueva aplicación web para gestionar diferentes procesos académicos y administrativos.

    La aplicación, denominada TxurdiGest, permitirá gestionar información relacionada con:

    • Alumnado.
    • Profesorado.
    • Personal administrativo.
    • Documentación académica.
    • Comunicación entre usuarios.

    El equipo de desarrollo debe decidir cómo construir la aplicación.

    Algunos miembros del equipo consideran que la seguridad debe añadirse cuando la aplicación esté terminada.

    Otros defienden que las decisiones relacionadas con la seguridad deben tomarse desde el inicio del proyecto.

    Ejemplo guiado¶

    Analiza las siguientes decisiones y relaciónalas con la fase del desarrollo en la que deberían plantearse.

    Decisión Fase del proyecto
    Definir qué tipos de usuarios existirán en la aplicación. Análisis
    Establecer qué acciones puede realizar cada usuario. Diseño
    Validar correctamente los datos introducidos mediante formularios. Implementación
    Comprobar que los mecanismos de seguridad funcionan correctamente. Pruebas

    La seguridad no aparece únicamente cuando la aplicación está terminada.

    Cada fase del desarrollo implica decisiones que pueden afectar a la seguridad final del sistema.

    Un error cometido en una fase inicial puede ser más difícil y costoso de solucionar posteriormente.

    Ejemplo aplicado a TxurdiGest¶

    El centro educativo quiere incorporar una nueva funcionalidad:

    Permitir que el alumnado entregue trabajos a través de TxurdiGest.

    Antes de comenzar la programación, el equipo debe analizar diferentes aspectos relacionados con la seguridad.

    Pregunta Fase relacionada
    ¿Qué usuarios pueden entregar trabajos? Análisis
    ¿Quién puede consultar los trabajos entregados? Diseño
    ¿Cómo se validan los archivos enviados? Implementación
    ¿Cómo comprobamos que la funcionalidad funciona correctamente? Pruebas

    La seguridad no consiste únicamente en añadir controles técnicos.

    También implica tomar buenas decisiones antes de escribir código.

    Comprueba que lo has entendido¶

    Responde a las siguientes preguntas:

    1. ¿Por qué no es recomendable añadir la seguridad únicamente al final del desarrollo?

    2. Un equipo decide almacenar las contraseñas de los usuarios directamente en la base de datos porque "la aplicación todavía no está publicada".

    3. ¿Qué problema existe en esta decisión?

    4. ¿En qué fase del proyecto debería haberse planteado una solución segura?

    5. Indica dos decisiones relacionadas con la seguridad que deberían tomarse durante la fase de diseño.

    Actividad individual¶

    Analiza el siguiente caso:

    Un equipo ha desarrollado una aplicación web durante seis meses.

    La aplicación funciona correctamente y todas las funcionalidades están terminadas.

    Antes de publicarla descubren los siguientes problemas:

    • No existe separación entre usuarios administradores y usuarios normales.
    • Los formularios no validan correctamente los datos.
    • Las contraseñas se almacenan sin protección.
    • No existe un sistema adecuado de registro de errores.

    Responde:

    1. ¿Qué problemas podrían haberse evitado si la seguridad se hubiera considerado desde el inicio?

    2. ¿Qué cambios serían más difíciles de realizar en este momento?

    3. Relaciona cada problema detectado con la fase del ciclo de desarrollo en la que debería haberse tratado.

    Taller colaborativo (ETHAZI)¶

    Situación¶

    El equipo de desarrollo de TxurdiGest debe diseñar una nueva funcionalidad:

    Entrega de trabajos del alumnado

    La funcionalidad debe permitir:

    • Que el alumnado pueda subir documentos.
    • Que el profesorado pueda consultar las entregas.
    • Que el sistema almacene la información necesaria.

    Antes de programar la funcionalidad, el equipo debe realizar un análisis inicial de seguridad.

    Trabajo a realizar¶

    En grupos, elaborad una propuesta de diseño inicial donde analicéis:

    Usuarios implicados¶

    Identificad los perfiles que participan:

    • Alumno.
    • Profesor.
    • Administrador.

    Para cada perfil indicad qué acciones debería poder realizar.

    Información gestionada¶

    Indicad qué información almacenará la aplicación:

    • Datos del alumno.
    • Documento entregado.
    • Fecha de entrega.
    • Estado de la entrega.
    • Información asociada a la evaluación.

    Riesgos posibles¶

    Identificad situaciones que podrían afectar a la seguridad:

    Ejemplos:

    • Un alumno consulta documentos de otro alumno.
    • Un usuario no autorizado modifica una entrega.
    • Se envía un archivo no permitido.
    • Se pierde información importante.

    Medidas de seguridad iniciales¶

    Proponed medidas que deberían considerarse antes de implementar la funcionalidad.

    Ejemplos:

    • Control de usuarios.
    • Control de permisos.
    • Validación de archivos.
    • Protección de datos almacenados.

    Entregable¶

    Cada grupo entregará un documento que incluya:

    • Descripción de usuarios y permisos.
    • Información gestionada.
    • Riesgos identificados.
    • Medidas de seguridad propuestas.

    Formato permitido:

    • Markdown.
    • PDF.

    Evidencias de aprendizaje¶

    Una propuesta adecuada debería demostrar:

    • Identificación correcta de usuarios y responsabilidades.
    • Relación entre riesgos y medidas de protección.
    • Comprensión de que la seguridad debe considerarse antes de implementar.
    • Capacidad para justificar decisiones técnicas.

    Errores habituales¶

    Algunos errores frecuentes son:

    • Pensar que la seguridad corresponde únicamente al administrador del sistema.
    • Considerar la seguridad una tarea final del proyecto.
    • Centrarse únicamente en que la aplicación funcione.
    • No analizar cómo podría utilizarse incorrectamente una funcionalidad.
    • Proponer medidas de seguridad sin relacionarlas con riesgos concretos.

    Para recordar¶

    • La seguridad debe formar parte del desarrollo desde el inicio.
    • Cada fase del ciclo de vida implica decisiones relacionadas con la seguridad.
    • Los errores detectados tarde suelen ser más difíciles de solucionar.
    • Un buen desarrollador no solo crea aplicaciones funcionales, sino aplicaciones preparadas para funcionar de forma segura.
