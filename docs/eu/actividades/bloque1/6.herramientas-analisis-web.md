# 6. jarduera. Web aplikazio bat tresna profesionalekin aztertzen

## Helburuak

Jarduera hau amaitzean gai izango zara:

- Web aplikazioak aztertzeko erabiltzen diren tresna nagusiak identifikatzeko.
- Lortu nahi duzun informazioaren arabera tresna egokia aukeratzeko.
- Web aplikazio baten HTTP trafikoa behatzeko.
- Sare-trafikoaren oinarrizko harrapaketa bat egiteko.
- DevTools, curl, Burp Suite eta Wireshark-en arteko desberdintasunak ulertzeko.

---

## Beharrezko materiala

Jarduera hau egiteko honako hau beharko duzu:

- "Tresna profesionalak" kapitulua.
- Web nabigatzailea.
- Nabigatzaileko DevTools.
- curl.
- Burp Suite Community.
- Wireshark.
- Interneteko konexioa.

---

## Testuingurua

Web aplikazio batek behar bezala funtzionatzen ez duenean, garatzaile batek zer gertatzen ari den jakin behar du.

Eskaera egokia bidali da?

Zerbitzariak erantzun du?

Saioko cookie-a sortu da?

Komunikazioak HTTPS erabiltzen du?

Galdera horiei erantzutea oso zaila litzateke analisi-tresnarik gabe.

Tresna bakoitzak aplikazioaren ikuspegi desberdina ematen du, eta horietako bakoitza noiz erabili jakitea web garatzaile ororen ohiko lanaren parte da.

---

## Adibide gidatua

Aplikazio bera ikuspuntu desberdinetatik azter daiteke.

| Jakin nahi dut... | Gomendatutako tresna |
|-----------------|-------------------------|
| Orri batek zer baliabide deskargatzen dituen | DevTools |
| Zer cookie erabiltzen dituen | DevTools |
| HTTP eskaera batek zer erantzuten duen | curl |
| Aplikazio batek egindako HTTP eskaera guztiak | Burp Suite |
| Sarean dabilen trafiko guztia | Wireshark |

!!! note

	Tresna batek ere ez du bestea ordezkatzen. Bakoitzak web aplikazio baten funtzionamenduaren ikuspegi desberdina eskaintzen du.

---

## TxurdiGest-era aplikatutako adibidea

TxurdiGest garatzen ari den bitartean, taldeak saio-hasierak ondo funtzionatzen duela egiaztatu nahi du.

Horretarako, honako hauek erabil ditzake:

- **DevTools**, deskargatutako baliabideak eta cookie-ak egiaztatzeko.
- **curl**, HTTP eskaera zehatz bat egiteko.
- **Burp Suite**, saio-hasieran egindako HTTP eskaera guztiak behatzeko.
- **Wireshark**, taldeak sortutako trafikoa bistaratzeko.

Tresna guztiek aplikazio bera aztertzen dute, baina bakoitzak informazio desberdina ematen du.

---

## Egiaztatu ulertu duzula

Erantzun hurrengo galderei.

1. Zer tresna erabiliko zenuke aplikazio bateko cookie-ak ikuskatzeko?

2. Zein erabiliko zenuke terminaletik HTTP eskaera bat egiteko?

3. Zer tresnak ahalbidetzen du aplikazio batek egindako HTTP eskaera guztiak behatzea?

4. Zer tresnak harrapatzen du sare-interfaze baten trafiko guztia?

---

## Banakako jarduera

### 1. zatia. DevTools

!!! example "Zuk zeuk probatu"

	Ireki edozein web orri.

1. Ireki DevTools.
2. Sartu **Network** fitxan.
3. Birkargatu orria.
4. Zenbatu gutxi gorabehera zenbat eskaera egiten diren.
5. Kokatu gutxienez HTML fitxategi bat, CSS bat, JavaScript bat eta irudi bat.

Erantzun:

- Zer baliabidek behar du denbora gehien deskargatzeko?
- Gutxi gorabehera zenbat eskaera agertzen dira?

---

### 2. zatia. Burp Suite Community

!!! example "Zuk zeuk probatu"

	Erabili Burp Suite-ren nabigatzaile integratua.

1. Abiarazi Burp Suite Community.
2. Ireki nabigatzaile integratua (**Open Browser**).
3. Sartu web orri batera.
4. Burp Suite-n hautatu **Proxy → HTTP History**.

Behatu erregistratutako informazioa.

Erantzun:

- Zenbat eskaera agertzen dira?
- Zer HTTP metodo ikusten dituzu?
- Zer egoera-kode agertzen dira maiztasun handienarekin?

!!! tip

	HTTP History-k automatikoki erregistratzen ditu nabigatzaile integratutik egindako eskaera guztiak, ohiko nabigatzailearen proxy-a eskuz konfiguratu beharrik gabe.

---

### 3. zatia. Wireshark

!!! example "Zuk zeuk probatu"

	Egin trafiko-harrapaketa sinple bat.

1. Abiarazi Wireshark.
2. Hautatu zure sare-interfazea.
3. Hasi harrapaketa.
4. Bisitatu segundo batzuetan web orri bat.
5. Gelditu harrapaketa.

Behatu harrapatutako paketeak eta erantzun:

- Zer protokolo agertzen dira?
- DNS trafikoa ikusten duzu?
- TLS konexioak ikusten dituzu?
- Gutxi gorabehera zenbat pakete harrapatu dira?

Ez da beharrezkoa paketeen edukia interpretatzea.

Helburua tresnarekin ohitzea baino ez da.

---

### 4. zatia. Zer tresna aukeratuko zenuke?

Lotu egoera bakoitza tresna egokienarekin.

| Egoera | Tresna |
|-----------|-------------|
| Aplikazio bateko cookie-ak ikustea | |
| HTTP eskaera eskuz egitea | |
| Aplikazio baten HTTP eskaera guztiak ikustea | |
| Sareko trafiko guztia harrapatzea | |

## Tresna profesionalak

### DevTools

Web orri baten funtzionamendua nabigatzailetik bertatik aztertzea ahalbidetzen du.

### curl

Komando-lerrotik HTTP eskaerak egitea ahalbidetzen du.

Bereziki erabilgarria da APIak probatzeko eta zerbitzariaren erantzunak egiaztatzeko.

### Burp Suite Community

Nabigatzailearen eta zerbitzariaren arteko proxy gisa jarduten du.

Aplikazio batek egindako HTTP eskaera eta erantzun guztiak behatzea ahalbidetzen du.

Jarduera honetan behaketa-tresna gisa bakarrik erabiltzen da.

### Wireshark

Sare-interfaze batetik dabilen trafikoa harrapatzen du.

Erabilitako aplikazioa edozein dela ere, komunikazio-protokoloak bistaratzea ahalbidetzen du.

---

## Aplikazioa erronkan

Erronka garatzean, tresna hauek lagun diezazukete:

- eskaera bat zerbitzarira behar bezala iristen dela egiaztatzen;
- saioko cookie-ak behar bezala sortzen direla egiaztatzen;
- API baten erantzunak berrikusten;
- aplikazioak HTTPS erabiltzen duela berresten;
- bezeroaren eta zerbitzariaren arteko komunikazio-arazoak detektatzen.

---

## Ohiko erroreak

!!! warning

	Ohiko errore batzuk hauek dira:

	- Burp Suite erasoak egiteko bakarrik balio duela pentsatzea.
	- Wireshark zibersegurtasunean bakarrik erabiltzen dela sinestea.
	- HTTP trafikoa eta sare-trafiko osoa nahastea.
	- Tresna bat aukeratzea, beste batek informazioa askoz errazago ematen duenean.

---

## Jardueratik harago

Hurrengo proposamenak borondatezkoak dira. Tresna hauen erabileran sakondu edo aukera berriak aurkitu nahi dituztenentzat pentsatuta daude.

### 1. proposamena

Arakatu Burp Suite-ren interfazea.

Kokatu atal hauek:

- Proxy
- HTTP History
- Repeater
- Target

Erabili gabe, saiatu bakoitzak zertarako balio duen ondorioztatzen.

---

### 2. proposamena

Egin harrapaketa bat Wireshark-ekin bideo bat erreproduzitzen edo fitxategi bat deskargatzen duzun bitartean.

Pakete kopurua handitzen da?

Zer protokolo berri agertzen dira?

---

### 3. proposamena

Bilatu Postman eta Insomnia-ri buruzko informazioa.

Zein egoeratan erabiliko zenituzke tresna horiek curl-en ordez?

---

!!! abstract "Ikertu"

	Tresna profesional askok web aplikazioak aztertzea ahalbidetzen dute.

	Bilatu horietako bati buruzko informazioa eta azaldu:

	- zein den haren helburua;
	- zer informazio mota ematen duen;
	- zein egoeratan izan daitekeen erabilgarria garatzaile batentzat.

---

## Gogoratzeko

- Tresna bakoitzak web aplikazio baten funtzionamenduaren ikuspegi desberdina eskaintzen du.
- DevTools-ek nabigatzailearen portaera aztertzen du.
- curl-ek terminaletik HTTP eskaerak egitea ahalbidetzen du.
- Burp Suite-k bezeroaren eta zerbitzariaren arteko HTTP mezuen trukea behatzen du.
- Wireshark-ek sare osoaren trafikoa harrapatzen du.
- Garatzaile on batek egoera bakoitzerako tresnarik egokiena aukeratzen daki.
