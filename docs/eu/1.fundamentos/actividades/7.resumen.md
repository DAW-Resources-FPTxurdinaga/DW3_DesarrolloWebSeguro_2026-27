# 7. jarduera. Web aplikazio baten analisiari buruzko txosten teknikoa

## Helburuak

Jarduera hau amaitzean gai izango zara:

- 1. Blokean zehar eskuratutako ezagutzak integratzeko.
- Informazio jakin bat lortzeko tresna egokia hautatzeko.
- Web aplikazio bat garatzaile baten ikuspegitik aztertzeko.
- Egindako behaketekin txosten tekniko labur bat prestatzeko.
- Aplikazio bat aldatu aurretik haren funtzionamendua dokumentatzearen garrantzia ulertzeko.

---

## Beharrezko materiala

Jarduera hau egiteko honako hau beharko duzu:

- Web nabigatzailea.
- DevTools.
- curl.
- Burp Suite Community.
- Wireshark.
- Interneteko konexioa.
- HTTPS bidez eskuragarri dagoen web aplikazio bat.

---

## Testuingurua

Garatzaile bat lehendik dagoen aplikazio batean lanean hasten denean, gutxitan hasten da zuzenean kodea idazten.

Lehenengo egiten duena aplikazioak nola funtzionatzen duen ulertzea da.

Horretarako, nabigatzailearen eta zerbitzariaren arteko komunikazioak aztertzen ditu, cookie-ak ikuskatzen ditu, HTTP eskaerak behatzen ditu eta aplikazioaren portaera orokorra berrikusten du.

Jarduera honetan prozesu hori bera egingo duzu, bloke honetan zehar ikasitako tresnak erabiliz.

Helburua ez da ahultasunak aurkitzea, baizik eta aplikazioaren funtzionamendua ulertzea eta lortutako informazioa dokumentatzea.

---

## Adibide gidatua

Web aplikazio bat aldatu aurretik, garatzaile batek honelako galderei erantzun ohi die:

- Aplikazioak HTTPS erabiltzen du?
- Nork jaulki du ziurtagiri digitala?
- Zer baliabide deskargatzen ditu nabigatzaileak?
- Zer cookie erabiltzen ditu?
- Zer HTTP eskaera egiten ditu?
- Zer trafiko sortzen du ekipoak?

Galdera horietako bakoitza tresna desberdin bat erabiliz erantzun daiteke.

| Lortu nahi dudan informazioa | Tresna |
|--------------------------------|-------------|
| Ziurtagiri digitala | Nabigatzailea |
| Deskargatutako baliabideak | DevTools |
| Cookie-ak | DevTools |
| HTTP eskaerak | Burp Suite |
| HTTP erantzun zehatza | curl |
| Sare-trafikoa | Wireshark |

!!! note

	Garatzaile profesional batek tresna desberdinak konbinatzen ditu aplikazio baten funtzionamendua ulertzeko, hura aldatu aurretik.

## TxurdiGest-era aplikatutako adibidea

Irudika ezazu garatzaile berri bat **TxurdiGest** proiektura batzen dela.

Funtzionalitate berriak inplementatzen hasi aurretik, aplikazioak nola funtzionatzen duen ulertu behar du.

Minutu batzuetan zehar, sistema tresna desberdinak erabiliz aztertzen du eta bere behaketak dokumentatzen ditu.

Prozesu horri esker, proiektuaren ikuspegi askoz osatuago batekin lan egin ahal izango du.

## Tresna profesionalak

Jarduera honetan hainbat tresna profesional erabili dituzu batera.

Bakoitzak aplikazio baten funtzionamenduaren ikuspegi desberdina ematen du.

- **DevTools**-ek nabigatzailearen portaera aztertzea ahalbidetzen du.
- **curl**-ek komando-lerrotik HTTP eskaerak egitea errazten du.
- **Burp Suite**-k bezeroaren eta zerbitzariaren arteko HTTP komunikazioak erregistratzen ditu.
- **Wireshark**-ek sare osoko trafikoa harrapatzen du.

Garatzaile batek denak konbinatzen jakin behar du, lortu behar duen informazioaren arabera.

---

## Aplikazioa erronkan

Proiektuaren iterazio berri bat hasi aurretik, taldeak prozedura bera erabil dezake aplikazioaren uneko egoera berrikusteko.

Diagnostiko honek aukera ematen du:

- sistemaren funtzionamendua ulertzeko;
- konfigurazio-errore posibleak detektatzeko;
- aplikazioak HTTPS erabiltzen duela egiaztatzeko;
- saioen portaera egiaztatzeko;
- funtzionalitate berriak inplementatu aurretik ikuspegi orokorra izateko.

---

## Ohiko erroreak

!!! warning

	Ohiko errore batzuk hauek dira:

	- Tresna bakarra aztertzea eta ondorio presazkoak ateratzea.
	- HTTP trafikoa sareko trafiko osoarekin nahastea.
	- HTTPSk bakarrik aplikazio bat guztiz segurua dela bermatzen duela pentsatzea.
	- Egindako behaketak ez dokumentatzea.

## Jardueratik harago

Hurrengo proposamenak borondatezkoak dira. Web aplikazioen analisian sakondu nahi dutenentzat pentsatuta daude.

### 1. proposamena

Alderatu bi web aplikazio desberdin.

Zer desberdintasun ikusten dituzu honako hauetan:

- eskaera kopurua;
- erabilitako cookie-ak;
- deskargatutako baliabideak;
- ziurtagiri digitala?

---

### 2. proposamena

Aztertu erronkan garatutako aplikazio bat.

Zer alderdi berrikusiko zenituzke Interneten argitaratu aurretik?

---

### 3. proposamena

Bilatu web aplikazioak aztertzeko ohikotasunez erabiltzen diren beste tresna batzuei buruzko informazioa.

Zein egoeratan izan litezke erabilgarriak garatzaile batentzat?

---

!!! abstract "Ikertu"

	Bilatu informazioa garapen-taldeek aplikazio bat argitaratu aurretik egiten duten berrikuspen teknikoaren prozesuari buruz.

	Bloke honetan aztertutakoez gain, zer alderdi egiaztatu ohi dituzte?

- Aplikazio bat aztertzea da hura aldatu aurreko lehen pausoa.

- Egindako behaketak dokumentatzeak talde-lana errazten du.
- Aplikazio baten funtzionamendua ulertzeak software seguruagoa garatzea ahalbidetzen du.

# 1. Blokearen itxiera

🎉 **Zorionak! Moduluaren lehen blokea osatu duzu.**

Jarduera hauetan zehar, web aplikazio baten funtzionamendua tresna profesionalak erabiliz behatzen ikasi duzu.

Orain gai zara:

- nabigatzaileak eta zerbitzariak nola komunikatzen diren ulertzeko;
- HTTP eskaerak eta erantzunak interpretatzeko;
- cookie-ak eta saioak aztertzeko;
- ziurtagiri digitalak eta HTTPS konexioak egiaztatzeko;
- DevTools, `curl`, Burp Suite eta Wireshark erabiltzeko, web aplikazio bati buruzko informazioa lortzeko.

Hurrengo blokean ikuspegia aldatuko duzu.

Orain arte aplikazio bat **behatu** egiten ikasi duzu.

Hemendik aurrera, **proiektuaren lehen faseetatik segurtasuna txertatuz diseinatzen eta garatzen** hasiko zara.

Hori da web garapen seguruaren benetako helburua.
