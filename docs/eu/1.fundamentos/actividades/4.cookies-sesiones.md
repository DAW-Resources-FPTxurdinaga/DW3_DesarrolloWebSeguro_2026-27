# 4. jarduera. Cookies eta saioak

## Helburuak

Jarduera hau amaitzean gai izango zara:

- HTTP zergatik den estatugabeko protokoloa ulertzeko.
- Cookie-ek saioa mantentzea nola ahalbidetzen duten azaltzeko.
- Saioko cookie bat eta cookie iraunkor bat bereizteko.
- Cookie baten segurtasun-atributu nagusiak identifikatzeko.
- Nabigatzaile batek gordetako cookie-ak DevTools erabiliz aztertzeko.

---

## Beharrezko materiala

Jarduera hau egiteko honako hau beharko duzu:

- "Cookies eta saioak" kapitulua.
- Web nabigatzailea.
- Garapen-tresnak (DevTools).
- Interneteko konexioa.

---

## Testuingurua

HTTP protokolo **estatugabea** da.

Horrek esan nahi du zerbitzarira bidalitako eskaera bakoitza aurrekoekiko independentea dela.

Mekanismo osagarririk gabe, zerbitzariak ezin izango luke jakin bi eskaera erabiltzaile berarenak diren ala ez.

Arazo hori konpontzeko **saioko cookie-ak** erabiltzen dira: nabigatzaileak gordetzen dituen datu txikiak dira, eta erabiltzailea eskaera desberdinen artean identifikatzea ahalbidetzen dute.

Horri esker, web aplikazio batean saioa hasita mantendu daiteke.

---

## Adibide gidatua

Irudika ezazu irakasle bat TxurdiGest-era sartzen dela.

1. Bere erabiltzailea eta pasahitza sartzen ditu.
2. Zerbitzariak bere kredentzialak baliozkotzen ditu.
3. Saio bat sortzen du.
4. Cookie bat bidaltzen dio nabigatzaileari.
5. Nabigatzaileak cookie hori gordetzen du.
6. Ondorengo eskaera bakoitzean, cookie-a automatikoki berriro bidaltzen da.

```
Saio-hasiera

		↓

Zerbitzariak saioa sortzen du

		↓

Zerbitzariak cookie bat bidaltzen du

		↓

Nabigatzaileak gordetzen du

		↓

Eskaera bakoitzak cookie-a barne hartzen du

		↓

Zerbitzariak erabiltzailea identifikatzen du
```

Cookie hori gabe, zerbitzariak ezin izango luke aitortu eskaera guztiak erabiltzaile berarenak direla.

---

## TxurdiGest-era aplikatutako adibidea

Irakasle batek ekintza hauek egiten ditu:

- Bere taldeak kontsultatzen ditu.
- Irakasgai bat irekitzen du.
- Hainbat kalifikazio sartzen ditu.
- Ikasleen zerrenda kontsultatzen du.
- Saioa ixten du.

HTTP eskaera independente batzuk izan arren, zerbitzariak badaki irakasle berarenak direla saioko cookie-ari esker.

## Banakako jarduera

!!! example "Zuk zeuk probatu"

	Aztertu erabiltzaile-kontu bat duzun web aplikazio bateko cookie-ak.

	Honako hauetako bat izan daiteke, adibidez:

	- Moodle
	- GitHub
	- Microsoft 365
	- Antzeko beste aplikazio bat

Egin honako pauso hauek:

1. Hasi saioa.
2. Ireki **DevTools**.
3. Sartu **Application → Cookies** atalean.
4. Hautatu dagokion domeinua.

Osatu hurrengo taula.

| Elementua | Behatutako balioa |
|----------|-----------------|
| Saioko cookie-aren izena | |
| Domeinua | |
| Iraungitze-data | |
| Secure | Bai / Ez |
| HttpOnly | Bai / Ez |
| SameSite | |

Ondoren, erantzun:

1. Zein cookiek ematen du erabiltzailearen saioa identifikatzen duela?

2. Secure eta HttpOnly atributuak aktibatuta ditu?

3. Zer balio du SameSite-k?

!!! tip

	Saioko cookie-ek, normalean, babes-mekanismo ugari izaten dituzte, hirugarrenek erabiltzea zailtzeko.

## Tresna profesionalak

### DevTools

DevTools-ek nabigatzaile batek domeinu jakin baterako gordetako cookie-ak ikuskatzea ahalbidetzen du.

Ohikotasunez erabiltzen den tresna da honako hauetarako:

- saioak egiaztatzeko;
- segurtasun-atributuak egiaztatzeko;
- autentifikazio-arazoak detektatzeko;
- web aplikazioak arazteko.

!!! note

	**HttpOnly** atributua duten cookie-ak DevTools-etik ikus daitezke, baina ezin dira JavaScript kodearen bidez irakurri.

---

## Aplikazioa erronkan

Erronka garatzean autentifikazio-sistema bat inplementatu beharko da.

Framework-ak saioak automatikoki kudeatzen baditu ere, taldeak hau ulertu behar du:

- zerbitzariak saioa sortzen du;
- nabigatzaileak cookie bat gordetzen du;
- ondorengo eskaera bakoitzak cookie hori automatikoki bidaltzen du;
- zerbitzariak informazio hori erabiltzen du erabiltzailea identifikatzeko.

Prozesu hori ulertzeak aplikazioa garatzea eta araztea erraztuko du.

---

## Ohiko erroreak

!!! warning

	Ohiko errore batzuk hauek dira:

	- HTTPk erabiltzailea automatikoki gogoratzen duela pentsatzea.
	- Saioa eta cookie-a nahastea.
	- Cookie guztiek informazio pertsonala gordetzen dutela sinestea.
	- Secure, HttpOnly eta SameSite atributuak ezikustea.
	- Cookie-ak ezabatzea, haien funtzioa ulertu gabe.

## Jardueratik harago

Jarduera nagusia amaitu baduzu, probatu hurrengo proposamenetako bat.

### 1. proposamena

Alderatu bi web aplikazio desberdinek erabiltzen dituzten cookie-ak.

Zer desberdintasun ikusten dituzu?

### 2. proposamena

Bilatu **Secure** atributua aktibatuta **ez** duen cookie bat.

Azal dezakezu zergatik?

### 3. proposamena

Alderatu saioko cookie bat eta beste cookie iraunkor bat.

Zer desberdintasun daude iraungitze-datan?

### 4. proposamena

Itxi nabigatzailea erabat.

Berriro ireki aplikazioa.

Cookie guztiak hor jarraitzen dute?

Zer aldatu da?

## Gogoratzeko

- HTTPk ez du informaziorik mantentzen eskaeren artean.
- Cookie-ek erabiltzaile baten saioa mantentzea ahalbidetzen dute.
- Cookie guztiek ez dute helburu bera.
- **Secure**, **HttpOnly** eta **SameSite** atributuek segurtasuna hobetzen dute.
- DevTools-ek web aplikazio batek erabiltzen dituen cookie-ak erraz ikuskatzea ahalbidetzen du.
- Cookie-en funtzionamendua ulertzea funtsezkoa da web aplikazio seguruak garatzeko.
