# Conclusiones

El despliegue es la última fase antes de que una aplicación sea utilizada por usuarios reales, pero no debe entenderse como un simple proceso de copiar archivos a un servidor.

Una aplicación segura necesita un entorno configurado de forma segura.

Durante este bloque hemos trabajado cómo trasladar las decisiones tomadas durante el desarrollo a un entorno real.

## Del código al entorno

A lo largo del módulo hemos visto que la seguridad depende de diferentes capas:

```text
Diseño seguro

        ↓

Implementación segura

        ↓

Configuración segura

        ↓

Despliegue seguro

        ↓

Mantenimiento
```

Un fallo en cualquiera de estas fases puede afectar a la seguridad de la aplicación.

## El código no funciona aislado

Una aplicación web depende de muchos elementos:

```text
Código

+

Servidor

+

Configuración

+

Base de datos

+

Red

+

Usuarios
```

Por este motivo, una aplicación correctamente programada puede quedar expuesta si se despliega con:

- secretos visibles;
- permisos incorrectos;
- servicios innecesarios;
- errores mostrados al usuario;
- bases de datos públicas.

## Principios aplicados durante el despliegue

Las decisiones trabajadas en este bloque se basan en varios principios:

### Separación de código y configuración

El mismo código debe poder ejecutarse en diferentes entornos.

```text
Desarrollo

Pruebas

Producción
```

Cada entorno aporta su propia configuración.

### Mínimo privilegio

Cada componente debe tener únicamente los permisos necesarios.

Ejemplos:

```text
Usuario de aplicación

≠

Usuario administrador
```

```text
Servicio público

≠

Servicio interno
```

### Reducir exposición

Una aplicación segura no publica todo lo que existe en el servidor.

Debe estar disponible únicamente:

```text
Lo necesario

para que la aplicación funcione
```

## Seguridad durante todo el ciclo de vida

El despliegue conecta directamente con las fases anteriores:

```text
Bloque 1

Comprender arquitectura y comunicaciones


Bloque 2

Diseñar teniendo en cuenta riesgos


Bloque 3

Implementar controles de seguridad


Bloque 4

Desplegar manteniendo esos controles
```

La seguridad no aparece en un único momento.

Es una característica transversal del desarrollo.

## Aplicación al proyecto

En los retos DAW, el objetivo no es únicamente conseguir que la aplicación funcione.

También debe poder justificarse:

- cómo se configura;
- cómo se protegen los secretos;
- cómo se limita el acceso;
- cómo se gestionan errores;
- cómo se mantiene después del despliegue.

Una aplicación profesional debe poder pasar de:

```text
Funciona en el equipo del desarrollador
```

a:

```text
Funciona de forma segura para usuarios reales
```

## Relación con SINF

El despliegue seguro requiere colaboración entre desarrollo e infraestructura.

Desde Desarrollo Web se debe comprender:

- qué necesita la aplicación;
- qué configuración espera;
- qué servicios utiliza;
- qué riesgos aparecen al publicarla.

La administración avanzada de sistemas pertenece a otros ámbitos, pero las decisiones de desarrollo deben considerar siempre el entorno donde la aplicación se ejecutará.

## Idea final

Una aplicación segura no termina cuando el código compila o cuando todas las funcionalidades funcionan.

Termina cuando:

```text
La aplicación

        +

La configuración

        +

La infraestructura

        +

Los procesos de mantenimiento

```

trabajan conjuntamente para proteger la información y a los usuarios.

> Desarrollar de forma segura significa pensar en la aplicación desde el diseño hasta su funcionamiento real en producción.
