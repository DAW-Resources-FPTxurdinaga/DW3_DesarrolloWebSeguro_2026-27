# Introducción al despliegue seguro

El despliegue es el proceso mediante el cual una aplicación pasa del entorno de desarrollo al entorno donde será utilizada por usuarios reales.

Este cambio de contexto introduce nuevas necesidades de seguridad.

Una aplicación que funciona correctamente en un equipo de desarrollo puede presentar riesgos cuando se publica si mantiene configuraciones, permisos o servicios pensados únicamente para trabajar durante la fase de programación.

## Del desarrollo a producción

Durante el desarrollo se busca principalmente facilitar la creación y prueba de la aplicación.

Es habitual disponer de:

- mensajes de error detallados;
- herramientas de depuración;
- datos de prueba;
- servicios locales;
- configuraciones temporales.

Estas condiciones no deben trasladarse directamente a producción.

Un entorno real debe estar preparado para usuarios externos y debe limitar la información y los accesos disponibles.

La transición debe revisarse:

```text
Desarrollo
    ↓
Pruebas
    ↓
Producción

Cada entorno tiene una configuración diferente
```

## Entornos de una aplicación

Una aplicación profesional suele utilizar varios entornos.

### Entorno de desarrollo

Es el entorno utilizado por el equipo durante la programación.

Puede incluir:

- herramientas de depuración;
- datos de prueba;
- configuraciones locales;
- servicios auxiliares.

Su objetivo es facilitar el desarrollo.

### Entorno de pruebas

Permite comprobar que la aplicación funciona antes de publicarla.

Debe ser lo más parecido posible a producción, pero sin utilizar datos reales innecesarios.

Permite validar:

- nuevas funcionalidades;
- correcciones;
- configuraciones;
- procesos de despliegue.

### Entorno de producción

Es el entorno utilizado por usuarios reales.

Debe priorizar:

- seguridad;
- disponibilidad;
- protección de datos;
- estabilidad.

No debe contener herramientas de desarrollo ni configuraciones temporales.

## La configuración forma parte de la seguridad

El mismo código puede comportarse de forma diferente según la configuración utilizada.

Por ejemplo:

```text
Mismo código

        ↓

Desarrollo
DEBUG activado
errores detallados

        ↓

Producción
DEBUG desactivado
errores controlados
```

Por este motivo, una aplicación segura debe separar:

```text
Código fuente
        +
Configuración del entorno
```

Esta separación permite utilizar la misma aplicación en diferentes contextos sin modificar el código.

## Errores habituales antes de publicar

Algunos problemas frecuentes durante un despliegue son:

### Mantener el modo depuración

Mostrar errores técnicos puede revelar:

- rutas internas;
- consultas SQL;
- nombres de archivos;
- información del servidor.

En producción, los errores deben gestionarse de forma controlada.

### Incluir secretos en el código

Ejemplos:

```php
$password = "clave_bd";
```

o:

```javascript
const apiKey = "clave_secreta";
```

Estos valores pueden acabar en:

- repositorios Git;
- copias de seguridad;
- otros entornos.

Los secretos deben gestionarse mediante mecanismos externos al código.

### Exponer servicios innecesarios

Un servidor no debería publicar todos los servicios disponibles.

La superficie de exposición debe limitarse:

```text
Servicios necesarios
        ↓
Accesibles

Servicios innecesarios
        ↓
No publicados
```

### Permisos incorrectos

Los archivos y directorios deben tener únicamente los permisos necesarios.

Una configuración demasiado permisiva puede permitir modificaciones no deseadas.

## Despliegue seguro como proceso

El despliegue no debe entenderse como copiar archivos al servidor.

Es un proceso de comprobación:

```text
Aplicación preparada
        ↓
Configuración revisada
        ↓
Secretos protegidos
        ↓
Servidor configurado
        ↓
HTTPS activo
        ↓
Permisos revisados
        ↓
Aplicación disponible
```

Cada paso reduce una posible fuente de riesgo.

## Relación con el ciclo de vida seguro

En bloques anteriores hemos trabajado:

- diseño seguro;
- implementación segura;
- validación y pruebas.

El despliegue es la siguiente fase:

```text
Diseño
   ↓
Código
   ↓
Pruebas
   ↓
Despliegue
   ↓
Mantenimiento
```

Una vulnerabilidad puede aparecer tanto por una línea de código incorrecta como por una configuración insegura del entorno.

## Aplicación a los proyectos DAW

En los retos del ciclo, la aplicación desarrollada debe pasar de un entorno de trabajo a un entorno accesible por usuarios.

Antes de publicar debería revisarse:

```text
¿Está activa la conexión HTTPS?

¿Los secretos están fuera del código?

¿La base de datos está protegida?

¿Los errores muestran información interna?

¿Los permisos son adecuados?

¿Solo están expuestos los servicios necesarios?
```

Estas comprobaciones forman parte del desarrollo profesional de aplicaciones web.

## Idea clave

> El despliegue seguro consiste en adaptar la aplicación y su entorno para que funcionen correctamente sin exponer información ni capacidades innecesarias.
