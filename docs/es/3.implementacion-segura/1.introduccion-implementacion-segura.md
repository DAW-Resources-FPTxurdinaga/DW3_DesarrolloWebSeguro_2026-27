# Introducción a la implementación segura

## Del diseño al código

En el bloque anterior aprendiste que una aplicación segura no surge por casualidad. Antes de comenzar a programar es necesario analizar los riesgos, diseñar la arquitectura y decidir cómo proteger la información y los recursos de la aplicación.

Sin embargo, un buen diseño no es suficiente.

Las decisiones tomadas durante la fase de análisis deben trasladarse correctamente al código. Una aplicación puede estar muy bien diseñada y seguir siendo vulnerable si los mecanismos de seguridad no se implementan adecuadamente.

En este bloque aprenderás a convertir esas decisiones en soluciones reales utilizando **JavaScript** y **PHP**.

---

## Programar de forma segura

Programar de forma segura no consiste en añadir seguridad al finalizar el desarrollo.

Significa escribir el código teniendo en cuenta la seguridad desde el primer momento.

Por ejemplo:

- validar los datos antes de utilizarlos;
- evitar mostrar información sensible al usuario;
- acceder a la base de datos mediante consultas preparadas;
- comprobar la identidad de los usuarios;
- verificar que cada usuario únicamente pueda realizar las acciones permitidas.

Cada una de estas medidas reduce la probabilidad de que la aplicación pueda ser utilizada de forma incorrecta o malintencionada.

---

## JavaScript y PHP trabajan juntos

Una aplicación web moderna ejecuta código tanto en el navegador como en el servidor.

Ambos entornos colaboran para ofrecer una buena experiencia de usuario y proteger la aplicación.

JavaScript permite realizar comprobaciones inmediatas que ayudan al usuario a introducir correctamente la información.

PHP recibe finalmente la petición y realiza las comprobaciones definitivas antes de procesar los datos.

Es importante comprender que **JavaScript mejora la experiencia del usuario**, mientras que **PHP protege la aplicación**.

Por este motivo, las comprobaciones realizadas en el navegador nunca sustituyen a las realizadas en el servidor.

## Implementar antes que memorizar

A lo largo de este bloque encontrarás numerosos ejemplos de código.

El objetivo no es memorizar funciones, instrucciones o fragmentos de código.

Lo importante es comprender:

- qué problema resuelve cada solución;
- por qué esa implementación es segura;
- cómo adaptarla a tu propio proyecto.

Cuando desarrolles el reto podrás volver a este tutorial para consultar los ejemplos y utilizarlos como referencia.

---

## Aprender a reconocer código inseguro

Tan importante como escribir código seguro es ser capaz de reconocer cuándo una implementación presenta un problema.

Por este motivo, algunos capítulos incluirán pequeños laboratorios basados en una aplicación deliberadamente vulnerable.

En ellos analizarás código inseguro, identificarás el problema y propondrás una solución más segura.

El objetivo no es aprender a atacar aplicaciones, sino desarrollar la capacidad de detectar errores de implementación y corregirlos.

## Organización del bloque

Todos los capítulos de este bloque seguirán una estructura similar.

En cada uno encontrarás:

- una explicación del problema;
- ejemplos de implementación en **JavaScript**;
- ejemplos de implementación en **PHP**;
- recomendaciones y buenas prácticas;
- errores habituales;
- una aplicación al proyecto desarrollado por tu equipo;
- un pequeño laboratorio para analizar y mejorar código inseguro.

Esta organización pretende que el tutorial pueda utilizarse tanto durante el aprendizaje como mientras desarrollas tu propio proyecto.

## Antes de continuar...

Durante este bloque no aprenderás únicamente **qué** mecanismos de seguridad existen.

Aprenderás **cómo implementarlos correctamente** y **cómo aplicarlos** en una aplicación web desarrollada con **JavaScript** y **PHP**.

Ese será el objetivo principal de todo el bloque.
