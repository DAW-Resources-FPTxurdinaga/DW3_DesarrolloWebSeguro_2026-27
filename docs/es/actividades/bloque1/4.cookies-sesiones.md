## Contexto

HTTP es un protocolo **sin estado**.

Esto significa que cada petición enviada al servidor es independiente de las anteriores.

Sin un mecanismo adicional, el servidor no podría saber si dos peticiones pertenecen al mismo usuario.

Para solucionar este problema se utilizan las **cookies de sesión**, pequeños datos almacenados por el navegador que permiten identificar al usuario entre distintas peticiones.

Gracias a ellas es posible mantener la sesión iniciada en una aplicación web.

---

## Ejemplo guiado

Imagina que un profesor accede a TxurdiGest.

1. Introduce su usuario y contraseña.
2. El servidor valida sus credenciales.
3. Crea una sesión.
4. Envía una cookie al navegador.
5. El navegador almacena esa cookie.
6. En cada petición posterior la cookie vuelve a enviarse automáticamente.

```
Inicio de sesión

        ↓

Servidor crea la sesión

        ↓

Servidor envía una cookie

        ↓

El navegador la almacena

        ↓

Cada petición incluye la cookie

        ↓

El servidor identifica al usuario
```

Sin esa cookie, el servidor no podría reconocer que todas las peticiones pertenecen al mismo usuario.

---

## Ejemplo aplicado a TxurdiGest

Un profesor realiza las siguientes acciones:

- Consulta sus grupos.
- Abre una asignatura.
- Introduce varias calificaciones.
- Consulta el listado de alumnos.
- Cierra la sesión.

Aunque son varias peticiones HTTP independientes, el servidor sabe que pertenecen al mismo profesor gracias a la cookie de sesión.

## Herramientas profesionales

### DevTools

DevTools permite inspeccionar las cookies almacenadas por un navegador para un determinado dominio.

Es una herramienta utilizada habitualmente para:

- comprobar sesiones;
- verificar atributos de seguridad;
- detectar problemas de autenticación;
- depurar aplicaciones web.

!!! note

    Las cookies con el atributo **HttpOnly** pueden visualizarse desde DevTools, pero no pueden ser leídas desde código JavaScript.

---

## Aplicación en el reto

Durante el desarrollo del reto será necesario implementar un sistema de autenticación.

Aunque el framework gestione automáticamente las sesiones, el equipo debe comprender que:

- el servidor crea una sesión;
- el navegador almacena una cookie;
- cada petición posterior envía automáticamente esa cookie;
- el servidor utiliza esa información para identificar al usuario.

Comprender este proceso facilitará el desarrollo y la depuración de la aplicación.

---

## Errores habituales

!!! warning

    Algunos errores frecuentes son:

    - Pensar que HTTP recuerda automáticamente al usuario.
    - Confundir sesión con cookie.
    - Creer que todas las cookies almacenan información personal.
    - Ignorar los atributos Secure, HttpOnly y SameSite.
    - Eliminar cookies sin comprender su función.

## Para recordar

- HTTP no mantiene información entre peticiones.
- Las cookies permiten mantener la sesión de un usuario.
- No todas las cookies tienen la misma finalidad.
- Los atributos **Secure**, **HttpOnly** y **SameSite** mejoran la seguridad.
- DevTools permite inspeccionar fácilmente las cookies utilizadas por una aplicación web.
- Comprender el funcionamiento de las cookies es fundamental para desarrollar aplicaciones web seguras.
