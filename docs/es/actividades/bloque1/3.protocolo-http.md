# Actividad 3. Protocolo HTTP

## Objetivos

Al finalizar esta actividad serás capaz de:

- Comprender cómo se comunican un navegador y un servidor mediante HTTP.
- Diferenciar una petición HTTP de una respuesta HTTP.
- Identificar los elementos principales de una comunicación HTTP.
- Interpretar métodos, códigos de estado y cabeceras básicas.
- Analizar comunicaciones HTTP utilizando herramientas profesionales.
- Realizar peticiones HTTP desde línea de comandos utilizando `curl`.

## Contexto

Cuando un usuario utiliza una aplicación web parece que simplemente interactúa con una interfaz gráfica.

Sin embargo, cada acción genera una comunicación entre diferentes componentes.

Por ejemplo, cuando un alumno consulta sus calificaciones en TxurdiGest ocurre una comunicación entre:

- El navegador del usuario.
- El servidor de la aplicación.
- La base de datos donde se almacena la información.

El navegador debe solicitar la información y el servidor debe responder con los datos correspondientes.

Esta comunicación se realiza mediante el protocolo HTTP.

Comprender HTTP es fundamental para cualquier desarrollador web, independientemente de la tecnología utilizada.

Una aplicación desarrollada con PHP, Laravel, Vue o cualquier otro framework seguirá utilizando peticiones y respuestas HTTP.

# Ejemplo guiado

Observa la siguiente petición HTTP:

```http
GET /calificaciones HTTP/1.1
Host: txurdigest.local
```

Esta petición contiene información importante:

| Elemento | Significado |
|----------|-------------|
| GET | Método utilizado para solicitar información |
| /calificaciones | Recurso solicitado |
| HTTP/1.1 | Versión del protocolo utilizado |
| Host | Servidor al que se dirige la petición |

El servidor procesa la petición y devuelve una respuesta:

```http
HTTP/1.1 200 OK
Content-Type: text/html
```

La respuesta también contiene información relevante:

| Elemento | Significado |
|----------|-------------|
| 200 OK | La petición se ha procesado correctamente |
| Content-Type | Tipo de contenido enviado |

Una comunicación web sigue siempre este modelo:

```
Cliente

   ↓

Petición HTTP

   ↓

Servidor

   ↓

Respuesta HTTP

   ↓

Cliente
```

# Ejemplo aplicado a TxurdiGest

Un profesor accede a TxurdiGest para consultar las calificaciones de su grupo.

El proceso podría ser:

1. El profesor abre la aplicación desde el navegador.
2. El navegador genera una petición HTTP.
3. El servidor recibe la petición.
4. La aplicación comprueba la información necesaria.
5. El servidor devuelve una respuesta.
6. El navegador muestra los resultados.

Analiza las siguientes preguntas:

### Comunicación inicial

- ¿Quién inicia siempre la comunicación?
- ¿Qué componente realiza la petición HTTP?

### Información enviada

La petición puede incluir:

- Recurso solicitado.
- Datos enviados por el usuario.
- Información del navegador.

### Información recibida

La respuesta puede incluir:

- Código de estado.
- Datos solicitados.
- Información sobre el resultado de la operación.

Aunque el usuario solo vea una pantalla, internamente se producen múltiples comunicaciones HTTP.

## Parte 2. Realizar peticiones HTTP con curl

`curl` es una herramienta utilizada habitualmente por desarrolladores para realizar peticiones HTTP desde la línea de comandos.

Permite probar APIs, analizar respuestas y diagnosticar problemas de comunicación.

---

### Petición GET básica

Ejecuta:

```bash
curl https://jsonplaceholder.typicode.com/users
```

Observa:

- Los datos recibidos.
- El formato de la respuesta.
- La información devuelta por el servidor.

Responde:

1. ¿Qué método HTTP se ha utilizado?
2. ¿Qué tipo de datos devuelve el servidor?
3. ¿La respuesta contiene información de varios usuarios?

---

### Consultar las cabeceras HTTP

Ejecuta:

```bash
curl -I https://jsonplaceholder.typicode.com/users
```

Analiza la información recibida.

Identifica:

- Código de estado HTTP.
- Tipo de contenido.
- Información del servidor.

---

### Realizar una petición POST

Ejecuta:

```bash
curl -X POST \
-H "Content-Type: application/json" \
-d '{"nombre":"Ana","curso":"DAW"}' \
https://jsonplaceholder.typicode.com/posts
```

Analiza:

- Método utilizado.
- Cabecera enviada.
- Datos incluidos en el cuerpo de la petición.

Responde:

1. ¿Qué diferencia existe entre GET y POST?
2. ¿Dónde se envían los datos en esta petición?
3. ¿Qué información devuelve el servidor?

# Herramientas profesionales

## DevTools del navegador

Las herramientas de desarrollo permiten observar las comunicaciones HTTP generadas por una aplicación web.

Son especialmente útiles para:

- analizar peticiones;
- revisar respuestas;
- comprobar códigos de estado;
- detectar problemas de comunicación.

---

## curl

`curl` permite realizar peticiones HTTP sin utilizar un navegador.

Es una herramienta utilizada habitualmente para:

- probar APIs.
- automatizar tareas.
- comprobar respuestas del servidor.
- diagnosticar problemas de comunicación.

Los desarrolladores utilizan herramientas como DevTools y `curl` para comprender qué ocurre realmente entre cliente y servidor.

---

# Aplicación en el reto

Durante el desarrollo de la aplicación del reto, el equipo debe tener en cuenta que todas las comunicaciones entre cliente y servidor utilizan HTTP.

Independientemente de la tecnología utilizada, la aplicación funcionará mediante intercambio de peticiones y respuestas.

Ejemplos:

Aplicación PHP:

```
Formulario HTML

      ↓

Petición HTTP

      ↓

Servidor PHP

      ↓

Respuesta HTTP
```

Aplicación con frameworks:

```
Componente frontend

      ↓

Petición HTTP a una API

      ↓

Servidor backend

      ↓

Respuesta HTTP
```

Durante el desarrollo del proyecto será necesario analizar:

- Qué datos envía el cliente.
- Qué información devuelve el servidor.
- Qué operaciones requieren protección.
- Qué respuestas recibe cada usuario.

Cuando el equipo implemente funcionalidades deberá ser capaz de interpretar las comunicaciones HTTP generadas por su propia aplicación.

---

# Errores habituales

Algunos errores frecuentes son:

- Pensar que el navegador controla la seguridad de la aplicación.
- Confiar en datos recibidos directamente desde el cliente.
- Ocultar una funcionalidad pensando que nadie podrá acceder a ella.
- No revisar los códigos de respuesta HTTP.
- Desconocer qué información se intercambia entre cliente y servidor.
- Utilizar APIs o peticiones HTTP sin comprender qué datos se envían y reciben.

---

# Para recordar

- HTTP es el protocolo utilizado para la comunicación entre cliente y servidor.
- Una aplicación web funciona mediante peticiones y respuestas.
- Las peticiones contienen información enviada al servidor.
- Las respuestas contienen el resultado de la operación solicitada.
- DevTools permite observar las comunicaciones generadas por el navegador.
- `curl` permite crear y analizar peticiones HTTP desde línea de comandos.
- El servidor siempre debe validar y proteger la información recibida.
