# Manual de estilo

Este documento define los criterios editoriales del proyecto.

Su objetivo es garantizar que todos los contenidos mantengan un estilo homogéneo, sean fáciles de consultar y aporten valor al alumnado.

---

# Finalidad del proyecto

Este proyecto no pretende ser un libro de texto.

Es un manual de consulta dirigido al alumnado de Desarrollo de Aplicaciones Web (DAW) para ayudarle a diseñar, implementar, desplegar y verificar aplicaciones web seguras mientras desarrolla los retos del curso.

Cada página debe resolver una necesidad concreta del alumnado.

---

# Principios editoriales

## Aportar valor

Todo apartado debe aportar información útil.

Si al eliminar un apartado el contenido sigue enseñando lo mismo, ese apartado sobra.

---

## Una página, una idea

Cada página debe responder a una única pregunta.

Ejemplos:

- ¿Qué es la validación de entradas?
- ¿Cómo validar un formulario en JavaScript?
- ¿Cómo utilizar consultas preparadas en PHP?

No deben mezclarse varios temas diferentes en una misma página.

---

## Explicar solo lo necesario

Evitar introducciones largas y textos de relleno.

El alumnado ya posee conocimientos de desarrollo web y acudirá al manual buscando una solución concreta.

---

## Priorizar ejemplos

Siempre que sea posible, explicar mediante:

- ejemplos;
- fragmentos de código;
- diagramas;
- comparaciones.

Reducir el texto cuando un ejemplo explique mejor el concepto.

---

## Escribir para desarrolladores

El tono debe ser técnico, claro y directo.

No utilizar lenguaje excesivamente académico ni frases innecesariamente largas.

---

# Contenido que debe evitarse

Evitar apartados como:

- Cómo trabajaremos durante el curso.
- Qué aprenderás.
- Qué no aprenderás.
- Organización del capítulo.
- Ruta de aprendizaje.
- Cómo estudiar este apartado.

La estructura de MkDocs ya proporciona esa información.

---

# Estructura recomendada

Las páginas conceptuales utilizarán únicamente los apartados que realmente sean necesarios.

Por ejemplo:

- ¿Qué problema resuelve?
- Conceptos.
- Ejemplo.
- Integración en TxurdiGest.
- Resumen.

Las páginas de implementación podrán incluir:

- Objetivo.
- Código.
- Explicación.
- Buenas prácticas.
- Errores habituales.
- Integración en TxurdiGest.

No es obligatorio utilizar todos los apartados.

---

# Ejemplos de código

Todo ejemplo debe:

- ser funcional;
- seguir buenas prácticas;
- estar comentado únicamente cuando sea necesario;
- poder adaptarse fácilmente al proyecto del alumnado.

No incluir código únicamente para ilustrar una explicación.

---

# Relación con los retos

Siempre que sea posible, conectar los contenidos con la aplicación desarrollada durante los retos.

El alumnado debe identificar fácilmente dónde aplicar cada técnica.

---

# Criterio editorial

Antes de dar una página por finalizada, responder a esta pregunta:

> ¿Este contenido ayudará al alumnado a desarrollar una aplicación web más segura?

Si la respuesta es no, el contenido debe revisarse o eliminarse.
